System map

One codebase, one image, two runtimes. Identity is the only path to the data plane.

Build

Every merge to main runs tests, builds one image and tags it with the full commit SHA. No latest.

Artifact

GHCR holds one immutable artifact. Both runtimes pull the same tag, so "it works on my machine" is the same machine.

Runtimes

Container Apps is serverless and scales to zero. AKS is Kubernetes: two replicas, probes, rolling update, a public LoadBalancer.

Identity

GitHub authenticates with OIDC. The workload authenticates with a managed identity on Container Apps and Workload Identity on AKS.

Data

Key Vault stores the secret; Blob stores the message. Both are reached through role assignments, never through keys or passwords.

Observability

Application logs and metrics, plus the Key Vault audit trail, land in one Log Analytics workspace.

The security thread

No secret in the pipeline, no key in the storage account, no direct role for the pipeline. One long-lived credential exists — the Easy Auth client secret — and it is a deliberate platform constraint.

Identity · no secrets

GitHub uses OIDC; the workload uses a managed identity. On AKS the token is projected by the Workload Identity webhook and exchanged with Entra ID.

kubectl -n azulab exec deploy/azulab -- env | grep AZURE_
RBAC · membership is the unit

The pipeline has zero direct roles; it inherits Contributor from azulab-deployers. Human vault access comes from azulab-platform-admins.

az role assignment list --assignee dce65f63-06be-435b-acc0-b0f6f2d1d751 --all --query "length(@)"
Key Vault · lifecycle

RBAC only, purge protection on, soft delete 7 days. The secret value is bootstrapped outside Terraform; the vault is managed, the value is not.

az keyvault show -n kv-azulab-dev-6mvarl --query properties.enablePurgeProtection
Storage · no key

Shared key authentication is disabled. The key still exists in ARM, but every data-plane use is rejected — Owner is control plane, not data plane.

az storage blob list --account-name stazulabdev6mvarl --container-name demo --auth-mode login
Audit · who read the secret?

Key Vault diagnostic logs go to Log Analytics. The identity claim is the managed identity's object id; the IP is the runtime's egress.

AzureDiagnostics | where ResourceType == 'VAULTS' | where OperationName in ('SecretGet','SecretList') | project TimeGenerated, OperationName, ResultType, CallerIPAddress, identity_claim_oid_g | order by TimeGenerated desc | take 20
Login · the one long-lived secret

Container Apps requires an Entra ID sign-in (Easy Auth). AKS stays public for the orchestration demo. Easy Auth is a confidential client, so one client secret exists — stored in the Container App secret store, never in Git.

curl -s -o /dev/null -w "%{http_code}" https://ca-azulab-dev.bluesand-12892b79.polandcentral.azurecontainerapps.io/
Pipeline
  1. 01Pull request — lint, unit tests, docker build, terraform validate.
  2. 02CI on main — tests, build, push ghcr.io/…:<sha>.
  3. 03CD — same tag to Container Apps and AKS, then smoke both.
  4. 04Verify — /health, /ready, and 401 on the protected Container App.
